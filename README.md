# NOFX 自托管改造版

自托管的 AI 量化交易系统：本地运行、自带 API Key、无强制付费墙、无官方云端依赖。

> 本项目源自 [nofx](https://github.com/NoFxAiOS/nofx)（AGPL-3.0），经过大幅改造后独立演进。

---

## 快速部署

Docker 一键启动，本地构建（不依赖任何预构建镜像）：

```bash
cp .env.example .env
# 编辑 .env：设置 JWT_SECRET / DATA_ENCRYPTION_KEY / RSA_PRIVATE_KEY
docker compose up -d --build
```

浏览器打开 `http://YOUR_SERVER_IP:3000`，后端 API 在 `:8080`。

常用运维命令：

```bash
docker compose logs -f nofx          # 后端日志
docker compose logs -f nofx-frontend # 前端日志
docker compose restart               # 重启
docker compose down                  # 停止
docker compose up -d --build         # 改代码后重新构建
```

生产环境建议启用 HTTPS（`.env` 中 `TRANSPORT_ENCRYPTION=true`，配合 Cloudflare / Caddy / Nginx 反代）。

## 核心特性

### 交易执行层

#### 1. 交易节流（Trade Throttle）

在 AI 决策真正下单前做一道闸门，避免高频噪声交易：

| 规则 | 行为 |
|---|---|
| 同一标的存在持仓 | 拒绝再次开仓（不做对冲） |
| 同一标的**同向**复入 | 平仓后 30 分钟内拒绝再入场 |
| 同一标的**反向**反手 | **放行** —— 平仓已通过最短持仓校验即可反手，不受 30 分钟冷却限制 |
| 持仓不足 15 分钟 | 拒绝平仓，**除非**价格较入场价 ≤ -3% 或 ≥ +8%（与杠杆无关） |

> 阈值均为**价格涨跌幅**口径（与杠杆无关），定义在 `trader/auto_trader_throttle.go`。
>
> 冷却与反手的判定均以**实际平仓成功**为准：平仓被拦截或失败时，反手同样会被拒绝，不会出现多空双持的对冲仓。

#### 2. 回撤监控（价格基准）

- 触发条件：价格相对入场价**顺向波动 ≥ +5%**，且从峰值利润**回吐 ≥ 40%** 时自动止盈平仓。
- 采用**价格基准**而非保证金基准 —— 高杠杆下不会再因微小波动误杀盈利单。
- 带入场价为 0 的保护，避免除零。

#### 3. 开仓保护与紧急平仓校验

- **止损强制**：未提供止损、或止损方向错误（多单止损 ≥ 现价 / 空单止损 ≤ 现价）→ **拒绝开仓**。
- **止盈可选**：未提供止盈可正常开仓；若提供则方向必须正确，否则拒绝开仓。
- **保护失败兜底**：止损或止盈在交易所下单失败时，立即平掉刚开的仓位，并校验交易所已无残留持仓、清理遗留挂单（重试 3 次）。

#### 4. 持仓保护调整（移动止损止盈）

AI 决策新增 `update_stop_loss` 动作：对已持仓标的移动止损（可同时移动止盈）。

- **只降风险**：多单止损只能上移、空单止损只能下移；止损必须始终位于现价正确一侧。
- **换单语义**：先撤销旧单、再挂新单；挂新失败会重试，仍失败则先尝试恢复旧止损，最后兜底按「开仓保护」策略紧急平仓（不留裸仓）。若仓位本就没有止损单，则直接补挂。
- **止盈可选**：与止损在同一条决策中携带；方向信号管理出场的策略自动跳过止盈调整；止盈换单失败不影响止损，也不会触发紧急平仓。
- **可见性**：AI 提示词中显示每个持仓的当前 SL/TP 价格；若当前止损价读取失败，该动作整体拒绝（fail-closed，不做任何改动）。
- 受 AI 决策周期约束（每周期检查一次）；不参与交易节流与最短持仓判定。

#### 5. 策略热重载

每个交易周期从数据库读取策略配置，检测到变更即重建策略引擎，**修改提示词/风控后无需重启服务**。

#### 6. 网格策略

- 支持区间震荡网格（高斯 / 金字塔 / 均匀分布）、ATR 自适应上下界、箱体突破检测与方向调整、网格偏斜自动再平衡（保留已成交仓位）。
- 初始化网格时按交易员配置自动设置**全仓/逐仓保证金模式**。

#### 7. AI 模型备用链（Fallback）

每个交易员可单独配置一个**备用模型**（交易员配置弹窗 → 「备用模型（可选）」，默认不启用）。主模型调用失败时由备用模型接管，避免"一次调用失败 = 整个周期没有决策"。

- **分流规则**：按失败的**耗时**判断，而不是按错误类型 —— 快速失败（< 30 秒，连接错误 / 429 / 5xx）先对同一模型重试 1 次；慢速失败（超时，约 180 秒）说明供应商侧已退化，直接切换备用模型。
- **预算约束**：周期 10 分钟，留给调用链约 6 分钟。因此**客户端内部重试已关闭**（统一 `WithMaxRetries(1)`），重试决策由 `trader/auto_trader.go` 的 `requestDecision()` 独占 —— 否则两层重试叠加会超出周期。最坏情况：主 180s + 备 180s = 360s。
- **无备用模型时**：行为与改造前一致（慢失败仍重试 1 次），只是重试的位置从客户端移到了调用处。
- **配置来源**：备用模型的 Key / URL / 模型名取自 `ai_models` 表（与主模型同一套映射），下拉里选一个即可，无需重复填写凭证。
- **归因**：每次决策在 `decision_records.ai_model_used` 记录**实际产出决策的模型**，日志中也有 `⚠️ switching to fallback model` / `✅ Decision produced by fallback model`，便于日后对比主备模型的决策质量。
- **注意事项**：备用模型必须能输出相同格式（`<reasoning>` + `<decision>` JSON）；不建议主备使用同一家供应商（同一故障域，等于没有备用）。

### 数据与配置层

| 能力 | 说明 |
|---|---|
| 无强制付费墙 | AI500 / OI 增减 / OI 指标等增强数据源均为 **UI 可选开关**；关闭后候选币池不再依赖它们（**注意**：每周期仍有一次 OITop 请求，见「已知问题 1」） |
| 币种来源 | 自定义静态币种列表 / AI500 / OI 增 / OI 减，可在策略中自由组合 |
| BYOK | 任意 OpenAI 兼容 API（自定义 BaseURL + Model + Key） |
| 多交易所 | 币安、Bybit、OKX、Bitget、KuCoin、Gate、Hyperliquid、Aster、Lighter、Indodax —— **建议优先使用币安**，理由见下方说明 |
| 自定义提示词 | 角色定义 / 交易频率 / 入场标准 / 决策流程等段落均可编辑 |

> **建议使用币安**：本项目的开发与测试以币安为主，其订单/仓位同步实现也最完整（基于水位的**增量同步** + `PositionBuilder` 完整仓位构建）。其他交易所虽然可用，但成交与历史仓位记录的完整性弱于币安 —— 它们的同步器是每轮重扫最近 24 小时 + 按成交 ID 去重，语义不同（详见「数据一致性」）。

### 数据一致性

交易记录（持仓 / 订单 / 成交 / 决策 / 权益快照 / 网格数据）均按**交易员 ID** 归属，相关规则：

- **交易员 ID 含创建时间戳**：交易员被删除后重建，会得到**全新的 ID**；旧 ID 下的历史记录不会归到新交易员名下。
- **删除级联**：删除交易员时，其名下全部交易记录一并删除（此前只删了权益快照，会残留孤儿记录）。
- **启动清理**：服务启动时清理「所属交易员已不存在」的孤儿记录；`traders` 表为空时跳过（全新安装/异常读取时避免误删）。
- **同步器生命周期**：交易所订单同步随交易员停止/移除而终止；重建交易员不会再遗留旧的同步器（旧同步器会以过期 ID 写入成交，导致平仓记录丢失）。
- **同步起点（币安）**：判据是**该交易所账户有无同步水位**——水位是 `trader_fills` 中该 `exchange_id` 的最后成交时间，**按账户而非按交易员**。
  - **有水位**（同一交易员重启）→ 从水位**增量续传**，不会漏掉停机窗口；
  - **无水位**（该账户从未有成交，或旧交易员的 `trader_fills` 已被级联删除）→ **从当前时刻开始，不回拉历史**。
  - 因此「删掉旧交易员 → 新建」会得到干净的白纸；但**同一账户下并存多个交易员会共享水位**。
  > **约定**：一个交易所账户只挂一个交易员。删除交易员**不会平掉交易所持仓或撤销挂单**，删前请自行清理——否则该持仓之后成交时找不到开仓记录，不会生成历史仓位。
  > 其他交易所的同步器实现不同（每次重扫最近 24 小时 + 按成交 ID 去重），如需同样的语义需另行改造。
- **平仓记录的产生**：仓位历史读的是 `trader_positions` 中 `status=CLOSED` 的记录，而它**不是由平仓动作直接写入的** —— 任何来源的平仓（AI 决策 / Web UI 一键平仓 / 交易所止损止盈 / App 手动平仓）都靠订单同步器事后补记：
  - 同步器拉到平仓成交 → `PositionBuilder.handleClose` 匹配到对应 `OPEN` 记录 → 写入出场价 / 平仓时间 / 已实现盈亏并置为 `CLOSED`；
  - **匹配不到 `OPEN` 记录则直接跳过**（日志 `No matching open position …, skipping`），这笔平仓不会留下任何历史。
  - 因此平仓要进历史需同时满足三条：① 交易员处于**启动**状态（同步器只在启动时运行）；② 水位线早于该成交；③ 库中存在对应的 `OPEN` 记录（AI 开仓会主动写，同步器发现开仓成交也会补建）。
  - Web UI 的一键平仓对币安**跳过立即写库**（`Close order will be synced by OrderSync, skipping immediate record`），完全依赖上述链路 —— 交易员停着时点平仓，当时不会有记录。
  - **停止 ≠ 重建**：停止期间平仓，重新启动**同一交易员**会从水位线续传并补记；**删除重建**则水位线随 `trader_fills` 级联删除，该笔平仓永久无法追溯。
  > 代码里另有从交易所「已平仓 PnL 列表」补记的兜底路径（`CreateFromClosedPnL` / `SyncClosedPositions`），但**没有任何调用方**，形同死代码 —— 平仓记录一旦错过就补不回来。

### 提示词分层机制

系统提示词由两部分组成，**修改方式与生效方式完全不同**：

| 层级 | 内容 | 修改方式 | 生效方式 |
|---|---|---|---|
| **自定义段（可编辑）** | 角色定义 / 交易频率 / 入场标准 / 决策流程 | Web UI 或数据库 | 保存后热重载，下个交易周期生效 |
| **硬编码段（不可编辑）** | 数据字典、Hard Constraints、仓位分级、输出格式 | 仅能改源码 | 需重新构建容器（`docker compose up -d --build`） |

**关键陷阱**：新建策略时，系统会把当时的**默认文案抄写进数据库**。此后该策略只读这份数据库副本 —— 代码里的默认值对**已存在的策略不再生效**。

- 改源码里的默认值 → 只影响**今后新建**的策略；
- 要改**已有策略**的四个段落 → 必须改数据库（或用 Web UI 编辑）。
- 代码兜底（**英文**）仅在某个段落**为空**时启用；四段全空会得到「中文数据字典 + 英文段落」的混合提示词。

> **口径一致性**：最短持仓 15 分钟同时存在于提示词（建议）与交易代码（强制，见「交易节流」）两处，修改时需保持两边一致，否则 AI 的行为预期与实际执行不符。

### 提示词一致性检查清单（改动前必读）

同一个「事实」在本项目里通常存在于 **4 个地方**，改一处忘三处就会产生**静默不一致** —— 不报错、不崩溃，只让 AI 收到错误或缺失的信息，只能靠人恰好读到提示词才会发现（历史上已发生过三次：UI 标注「代码强制」但代码未强制、`Profit` 公式多乘一次杠杆、节流的 15 分钟规则未写进提示词）。

| 位置 | 例子 |
|---|---|
| 代码配置 / 常量 | `RiskControl.MaxMarginUsage = 0.9`；`autopilotMinHoldDuration = 15min`（`trader/auto_trader_throttle.go`） |
| 提示词文本 | `Max Total Margin Usage: ≤90% of equity`（`kernel/engine.go` 动态渲染）；节流那几行（硬编码文字） |
| UI 文案 | 「最大保证金使用率（**代码强制**）」（`web/src/i18n/strategy-translations.ts`） |
| 数据字典 | `kernel/schema.go` 的 `DataDictionary`（字段含义与公式，随提示词一起发给 AI） |

**改这些地方时逐项对照检查**：

- 改**风控配置字段**（`store/strategy.go` 的 `RiskControlConfig`）→ 提示词是否按新字段渲染（`kernel/engine.go` 的 `BuildSystemPrompt`）；UI 文案是否仍准确，尤其「（代码强制）」四个字必须名副其实
- 改**节流 / 开仓保护的常量**（`trader/auto_trader_throttle.go`、`trader/auto_trader.go`）→ 提示词里那几行硬编码文字（`Min Hold Before Close` / `Re-entry Cooldown`）要同步，并在常量处保留交叉引用注释
- 改**指标计算口径**（`market/data.go`）→ `DataDictionary` 里的公式描述要同步
- 改**数据字段语义** → 同时更新 `DataDictionary`，否则 AI 会按错的含义理解数据

> **建议的防护手段（尚未实现）**：写 `kernel/prompt_*_test.go`，用**非默认配置**渲染提示词并断言关键片段存在（如 `Max Total Margin Usage: ≤80%`、`Min Position Size: ≥25 USDT`）。**必须用非默认值** —— 用默认值会假通过。可进一步在 `Dockerfile.backend` 的 builder 阶段加 `RUN go test ./kernel/ -run TestPrompt -count=1`，让不一致直接阻断镜像构建（**不要**写 `go test ./...`，仓库里有需要联网/凭证的测试）。

## 架构概览（数据流）

```
数据源
  ├── 币安公开行情接口 → K 线（直连，主路径）+ premiumIndex（资金费率，1h 缓存）
  └── CoinAnk 免费中转 → K 线兜底（币安未上市标的 / 币安不可用）
              │
              ▼
        本地计算指标
        EMA20/EMA50 · MACD · RSI7/14
        ATR14 · BOLL(20,2) · 成交量
              │
              ▼
        AI Prompt 渲染 → BYOK LLM
              │
              ▼
  交易节流 → 保护校验 → 交易所下单
```

> **注意**：K 线优先直连币安 —— 未走完的 K 线为实时数据（价格与成交量持续更新）；币安未上市标的或币安接口不可用时，回退 CoinAnk 中转。资金费率直连币安。

## 已知问题

1. **`kernel/engine.go` 无条件请求 `nofxos.ai`**
   每个交易周期都会执行 `GetOITopPositions()`，不检查用户是否启用了 OI 数据。失败会被静默忽略，但每轮都会发起一次外部请求。建议加一个默认关闭的开关。

2. **K 线数据源（已优化）**
   K 线现优先**直连币安**（含未走完 K 线的实时价格/成交量），CoinAnk 降级为兜底，仅在币安未上市标的或币安接口不可用时使用；此类非币安标的仍受 CoinAnk 可用性影响。

3. **止损挂单失败会触发“开仓即平仓”**
   开仓后若交易所侧 `SetStopLoss` 因瞬时网络抖动失败，会立即紧急平掉刚开的仓位。若交易所止损接口持续不稳，可能出现“开→即平→再开”的反复，白交手续费与滑点。建议在止损接口可靠的环境使用；可关注日志中 `failed to set mandatory stop loss` 的出现频率。

4. **指标周期输入不生效（UI 装饰性配置，暂不修改）**
   策略 UI 中的 RSI / EMA / ATR / BOLL 周期输入框（默认 `7,14`、`20,50`、`14`、`20`）只影响提示词里的一行描述文字（`(periods: ...)`），**实际计算全部硬编码**：EMA20/EMA50、RSI7/RSI14、ATR14、BOLL(20,2)、MACD(12,26,9)，调用点集中在 `market/data.go` 的 `calculateTimeframeSeries` / `calculateIntradaySeries` / `calculateLongerTermData`。填写非默认周期不会改变计算结果，且提示词描述会与实际数据不一致——**建议保持默认值**。
   将来若要支持自定义周期：底层 `calculateEMA` / `calculateRSI` / `calculateATR` / `calculateBOLL` 已支持传入 period 参数，主要工作是把策略配置透传到这些调用点，并同步改造展示标签与数据结构（`TimeframeSeriesData` 中 `RSI7Values` / `RSI14Values` / `EMA20Values` 等为固定字段，需改为动态结构）。
