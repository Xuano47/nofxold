## 快速部署

### 方式 A：一键脚本部署（推荐，免克隆代码、自动初始化）

#### 🐧 Linux / macOS
```bash
curl -fsSL https://raw.githubusercontent.com/Xuano47/nofxold/merged/install.sh | bash
```
- **安装位置**：默认装到 `~/nofxold`。
- **常用管理**：装完可以直接用全局命令 `nofxold [logs|restart|stop|update|status]`（或在安装目录跑 `./nofxold.sh`）。
- **网络与安全**：大部分交易所的 API 在中国大陆无法直连，请用海外服务器（新加坡/日本节点最稳，香港价格最优）。云服务器（腾讯云/阿里云/AWS 等）记得在安全组放行 `3000` 端口；**强烈建议只对自己的 IP 开白名单**，别向 `0.0.0.0/0` 裸露。

#### 🪟 Windows (PowerShell)
按 **Win + R** 输入 **powershell** 回车打开，粘贴执行：
```powershell
irm https://raw.githubusercontent.com/Xuano47/nofxold/merged/install.ps1 | iex
```
> 请用系统自带的 **PowerShell**，别用老的 CMD。
- **前置条件**：提前装好并启动 [Docker Desktop](https://www.docker.com/products/docker-desktop/)（左下角显示绿色 Running）。
- **使用方式**：自动安装到 `%USERPROFILE%\nofxold` 并拉起浏览器打开页面；后续在安装目录运行 `.\nofxold.bat [logs|restart|stop|update|status]` 管理。

## 核心特性

### 一、代码级硬风控（不靠大模型“自觉”）

1. **交易节流（Trade Throttle）**：
   - **防对冲**：同币种已有持仓时直接拒开新仓。
   - **冷静期**：同向平仓后默认冷静 15 分钟（可自定义时长或填 `0` 禁用），减少频繁追涨杀跌；反向反手不限制。
   - **锁仓防洗**：持仓不满 15 分钟不准主动平仓（价格较入场价亏损 `≤ -3%` 或盈利 `≥ +8%` 时例外放行）。
2. **开仓强制带止损**：
   - 没有合法止损价的开仓单直接拦截。
   - **裸仓兜底**：如果交易所挂止损单失败，代码立刻市价平掉刚开的仓位并撤掉残留挂单，不留裸仓。
3. **动态追踪止损**：
   - 支持 `update_stop_loss`：只允许上移多单止损、下移空单止损（只降风险不扩损）。
   - 改单采用先撤旧单再挂新单，失败会自动恢复原止损。
4. **价格基准回撤止盈**：
   - 浮盈达到入场价 `+5%` 以上，且从最高点回吐 `≥ 40%` 时，代码自动触发平仓锁利。按价格涨跌幅算，不会被高杠杆放大误杀。
5. **杠杆与仓位上限互锁**：
   - 支持 1~125X 杠杆配置，开仓前自动同步交易所杠杆。
   - 单币最大名义持仓直接按账户总净值动态换算成 USDT 限额传给模型，并在下单前代码强校验，超额直接拒单。

---

### 二、AI 决策引擎

1. **用自己的大模型 API（8 个自定义槽位）**：
   - 走标准 OpenAI 兼容接口（POST `/chat/completions`），支持 DeepSeek、OpenAI、Claude、Qwen、本地 Ollama / vLLM 或各类中转。
2. **持仓记忆（Thesis + 状态备注）**：
   - AI 开仓时必须写一句入场理由（`thesis`，≤35 字），整个持仓期间固定不变，每轮巡检都带给模型看；
   - 观望或移动止损时更新一句状态备注（`status_note`），帮模型保持前后逻辑连贯，不会刚开没几轮就忘了自己为什么进场。
3. **屏蔽历史盈亏干扰**：
   - Prompt 里故意不喂历史胜率、近期平仓盈亏统计，让模型只看当前盘面、账户净值和活着的持仓，少受上一单亏钱后的情绪影响。
4. **主备双模型容灾**：
   - 每个交易员可以配一个备用模型，主模型超时或接口报错时自动切备用重试，不会直接轮空。
5. **策略热更新**：
   - 网页里改完提示词和风控参数点保存，下一轮就生效，不用重启容器。
6. **双档 K 线模式（精简模式省 ~75% Token）**：
   - **精简模式（默认）**：后台依然拉 30~100 根 K 线把 EMA/RSI/MACD/ATR 全算准，但发给模型的表格只保留区间高低点 `Range`、现价所处分位 `Position in Range`、区间涨跌幅以及最近 5 根 K 线，大幅减少模型注意力分散和 API 账单。
   - **完整模式**：需要模型看完整 30~100 根 K 线表格时，可以在策略编辑页随时切换。

---

### 三、订单流分析（Order Flow）

直接用币安 K 线里自带的主动买入成交量算出（非币安交易所交易时也以币安数据作参考，深度更有保障），不靠昂贵的第三方逐笔接口：

* **1h 已收盘净买卖差与比例（`1h_closed_delta`）**：上一根已走完的 1 小时 K 线主动买减去主动卖的净额与占比。
* **15m 近期走势（`15m_closed_delta_3bar`）**：最近 3 根已收盘 15 分钟 K 线的净额序列，看资金是在持续抢筹还是衰竭。
* **未收盘实时预警（`1h_forming_delta` / `15m_forming_delta`）**：单独标出当前还没走完的那根 K 线（带进度百分比 `elapsed`），和已收盘数据分开展示不混用。

---

### 四、数据同步与稳定性

1. **增量水位同步**：
   - 按数据库 `trader_fills` 里记录的最后成交时间断点续传，停机或重启后不会漏单，也不会把建号之前的老成交扫进来污染记录；平仓配对和已实现盈亏统一由 `PositionBuilder` 结算。
2. **交易员数据隔离**：
   - 每个交易员带独立唯一 ID，删交易员时连同其名下的订单、成交、快照和网格记录一起清理；服务启动时自动清理残留孤儿记录。

## 数据流概览

```
数据源
  ├── Binance / OKX / Gate 公开接口 → 各自 K 线、资金费率、持仓量 OI
  ├── Binance 1h/15m 成交量 → 订单流 Order Flow（全所共用参考）
  └── CoinAnk → 兜底未在直连所覆盖的标的或周期
              │
              ▼
        本地指标计算
        EMA20/EMA50（对齐已收盘）· MACD · RSI7/14 · ATR14 · BOLL(20,2)
              │
              ▼
        精简/完整双档渲染（标出 forming 未收盘 K 线）
              │
              ▼
        XML 结构化 Prompt → 自定义大模型（支持主备切换）
              │
              ▼
   代码级节流与防呆纠偏 → 止损校验与裸仓兜底 → 交易所下单
              │
              ▼
   OrderSync 增量水位同步（带世代守卫）→ PositionBuilder 仓位结算
```
